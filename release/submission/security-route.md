# Private security-report route

Status: proposed for the future public GitHub repository; no route is live yet. Ordinary product support is planned through public Issues. Security and privacy incidents need a private intake so reporters do not have to expose project paths, logs or credentials in an issue.

The recommended launch route is GitHub private vulnerability reporting on the public `joebenscoter86/after-effects-studio` repository. A repository administrator must enable it, confirm that JB Technology LLC's responsible maintainer receives notifications, and test the reporter flow before the support and privacy pages point to it. GitHub's [configuration instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) and [reporter instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) describe the feature. This route avoids making a dedicated support email a launch prerequisite.

Joe Benscoter, acting for publisher JB Technology LLC through the `joebenscoter86` repository account, owns triage. Grant report access only to repository maintainers who need it. Ask reporters for a minimal reproducer and redacted logs; do not request an AEP, client artwork or credentials by default. Record the report in GitHub's private thread, keep only the diagnostic material needed to investigate it, and remove locally downloaded copies when the case closes. If a reporter asks to correct or delete material they supplied, handle the request in the same private thread and remove what the maintainer controls; explain that GitHub's own retention and backups are governed by GitHub. Review old closed reports periodically for unnecessary attachments. No response deadline is promised.

Before publication, enable the route, confirm notifications reach the responsible maintainer and test the reporter entry point without posting a sensitive example. If GitHub's private reporting is unavailable or unsuitable, choose and verify another private contact route before the public support page goes live.
