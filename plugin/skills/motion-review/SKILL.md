# Motion review

Read `quality` and `failure-atlas` through `ae_library`; use `reference-study` when judging against a reference. Inspect actual frames and timing, not just layer counts or a script. During review-only requests make no project changes; provide specific defects and the smallest useful corrections. During a build, fix issues in scope and re-render the affected section.

State what was reviewed (project, comp, version, times, export), then rank findings by viewer impact. Check: message clarity; hierarchy; typography; staging; pacing; spatial continuity; asset and edge quality; render correctness. Provide concrete evidence (time/frame, layer, screenshot) for each finding. Distinguish technical validation, visual judgment and user approval.

Avoid scores that pretend to predict reach. Event density is a craft choice. A technically clean but generic result is not ready if the brief demands distinctive motion. A gorgeous still does not prove motion pacing or audio sync. Report unperformed playback/audio checks plainly.
