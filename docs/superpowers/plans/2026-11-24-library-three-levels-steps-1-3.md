# Library three levels: plan for build steps 1 to 3

Spec: `docs/superpowers/specs/2026-11-24-library-three-levels-design.md`. Scope: schema and catalog build, the tool (`browse`, cross-level `find`, `get` for any level), and the visual styles moved into the catalog. Not here: runnable worlds, the user shelf, skill and server-instruction wording, new recipes, a release.

## What the code is today (checked 2026-11-24, base 741342b)

- `plugin/library/arsenal/` is written by `tools/channel-learner/arsenal.mjs` from `product/arsenal-drafts/` (recipe drafts `<video>.md`, `tags.json` keyed `<video>#<n>`, `proof-stills.json`, `CREDITS.md`) through `catalog.mjs buildCatalog`. Re-running it on `main` reproduces the shipped folder byte for byte. Stills are made once with ffmpeg from proof renders and then kept; the README gallery and the library manifest are rewritten in the same run.
- `ae_arsenal` (`plugin/runtime/src/tools/arsenal.ts`) has `find` (by job, technique kind only), `get` (one recipe by id, warns on a pinned revision that differs), `jobs`. The job ranking mirrors `catalog.mjs findTechniques`.
- Styles: `plugin/library/styles/index.json` plus one folder per style, generated by `plugin/scripts/import-styles.mjs` from Content's `production/styles` (proofs are deliberately not copied). Each style's `STYLE.md` is the `ae_library` document `style-<id>`. 31 styles; none has a picture in the plugin. Content holds a proof movie and sheet for 27 of them; engraving, game-show and microgame have none, and pixel-headline is the plugin's own with no proof render.
- 101 recipes, 76 with stills. The 25 without are 10 build aids, 14 unproven techniques and one unmatched recipe.
- The runtime has no JPEG decoder and its sheet font draws digits only, so it cannot compose a labelled contact sheet from the JPEG stills without a new dependency.

## Decisions

1. **One drafts-side source for the new fields**: `product/arsenal-drafts/levels.json` holds the `provides` vocabulary, each recipe's `provides` and renderer, and each style's level, `provides`, cost, proof beat and `composes`. `tags.json` is untouched, so recipe revisions (hashes of the draft text) do not move and pinned `<id>@<revision>` stays valid.
2. **Shipped catalog shape**: `catalog.json` keeps `vocab`, `version` and `jobs`, gains `provides` (the vocabulary) and `levels`, and its list is renamed `entries`. Every entry carries `level`, `provides`, `cost`, `composes`, `shelf: shipped`; recipes keep every field they had.
3. **Still required, or marked**: an entry has a `still`, or `still: null` with a `no_still` reason. The build refuses a proven technique or a style with a proof movie and no still, and any entry with neither. `browse` hides entries with no still unless asked, and says how many it hid.
4. **Styles**: one entry per style, id `style-<id>` (the `ae_library` document id), `kind: style`. The four 3D styles (backrooms, glass-product, lowpoly-island, tilt-shift) are `level: world` with `also_level: [direction]`; the rest are `level: direction`. A level query matches `level` or `also_level`. Stills come from the style's Content proof movie at the "picture" beat (never the "input" beat, which shows the author's own face; the build refuses it), 480 wide like recipe stills, made once and kept.
5. **`provides`**: strings `key` or `key: word`, from a fixed vocabulary of keys and words. A query `material` matches any material; `material: glass` matches only that word.
6. **`browse`**: a page of tiles (default 12, at most 24): one text legend with id, name, level and `provides` per tile, then each tile as a label line and its still. Not one composed image: that needs a JPEG decoder the zero-dependency runtime does not have (noted for later).
7. **`find`**: `job` behaves exactly as today (styles are never `technique`). `level` and/or `provides` without `job` returns entries across levels, proven first, then by how many asked `provides` they match.
8. **`get`**: any id. A style returns a header, its catalog record and its `STYLE.md` through the same reply `ae_library` gives (whole or outline), with its still.

## Steps

1. `levels.json` with vocabulary, recipe `provides`/renderer, style records (TDD on the builder: refuses unknown keys/words, missing recipes/styles, entries with no still and no reason, an input-beat still).
2. `arsenal.mjs`: read `levels.json` and `styles/index.json`, write style entries and stills, rename to `entries`, gallery covers styles. Regenerate; check recipe revisions unchanged.
3. Runtime `arsenal.ts`: `entries`, `browse`, cross-level `find`, `get` for styles, `jobs` returns the vocabulary. Tests first.
4. Rebuild dist, tools doc, Claude package; full test runs; acceptance check through the built server.
5. PR with the spec's differences noted.
