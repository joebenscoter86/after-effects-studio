# Comp Room 0.4.1: fixes from the finish-line reel

Status: design for Joe's approval, 2026-11-16. Nothing is built.

## Intent

Comp Room is Joe's own tool first. He may share it with professional motion designers to test, and show it on his socials. It will never be sold. So it has to work well for a stranger without becoming a product that needs support. Nothing in it embarrasses him if shared: it is a workflow, nothing personal.

The changes come from three sources:
- the steering study of the posted finish-line reel: Content repo, `docs/2026-11-16-finish-line-steering-study.md`, last section, on branch `adobe/motion-steering-study-88dac1`;
- the channel learner's motion-edge cut-out;
- a check command that already fails on `main`.

The work is split into two releases (Joe chose this):
- **0.4.1, soon:** code and guidance fixes. Building them needs no After Effects; each one that touches After Effects gets one short live check before release.
- **0.4.2, later:** the work that needs After Effects time (outline at the end). It gets its own design.

## Who the defaults serve

Decided with Joe:
- The shipped default is the sensible one for a stranger. Joe's own preferences live in his Content repo, which every one of his builds reads, so he gets his way without any setup.
- The likely outside testers are experienced motion designers, not beginners. Where a choice suits Joe because he is an expert (the reviewer), it suits them too and becomes everyone's default.

## 0.4.1 scope

1. **Deep Glow licence check (bug).**
   - The problem: `pixelheadline.jsx` picks Deep Glow when `hasEffect("PEDG2")` is true. That is also true when Deep Glow is installed but unlicensed, so the trial watermark renders. In the finish-line build the agent then dropped the glow entirely instead of using the stock fallback.
   - The fix: a shared check that a third-party effect is usable, not only installed.
   - How it tells (my call): aescripts products write a licence file, `~/Library/Application Support/com.aescripts.<Product>.lic`.
     - On Joe's Mac, `com.aescripts.DeepGlow2.lic` is dated 2026-11-15 20:06, after the finish-line build that showed the watermark, so this file is exactly what was missing then.
     - The check is a small table of known watermarked effects: match name, then licence file (`PEDG2` maps to `DeepGlow2`). An effect in the table with no licence file counts as unlicensed. An effect not in the table counts as usable, as today.
     - A per-call argument (`licensed: true`) lets a user with a licence stored elsewhere override the check.
     - No probe render, so the check adds no build time.
   - CorridorKey (`BsklCorKey`) has the same kind of trial watermark (a red cross until licensed). It goes in the table only once its licence file's name is confirmed on a licensed install; until then it is not listed.
   - When the check fails, the build uses the documented stock fallback and the build report says so: "Deep Glow is installed but not licensed; used the stock glow".
   - Tests (licence file mocked): installed and licensed, installed and unlicensed, not installed, and the override.
   - Naming (my call): effect match names and product names inside this compatibility table are fine; the pixel-headline style already names Deep Glow. The "no names" rule covers people, Joe's brands and creators, not the third-party effects a build depends on.

2. **Object Matte time warning.**
   - Today, before the soft-edge pass (which runs the matte twice), an agent can go quiet for 25 minutes; on Joe's Mac it took about 1 s a frame, 25 minutes for 1,377 frames.
   - The fix, as guidance only, with no interface change (my call): before any long subject pass, the agent estimates the time and tells the user, then starts it.
     - The passes: `subject.render_cutout`, the self-check renders of `soften_edge`, `check_file` on a long file, and the render of `motion_edge`.
     - The estimate: time a short span on the user's own machine (for example `ae_render_frame` on a few frames, or a few-second render), then multiply by the frame count.
     - `subject.render_cutout` is one blocking call, so its reply would come too late to carry the warning.
   - Figures already shipped (the 986 s and "2 minutes of render per 4K second" on the motion-edge branch, the 390 s for 320 frames behind the timeout, the 19 GB cache note) stay as reference. Each is labelled as measured on one machine. The warning to the user always comes from the user's own timing, never from these.
   - Where: the keying reference's Object Matte section, and the motion-studio skill's guidance on long renders.

3. **Motion-edge cut-out, `subject.motion_edge`.**
   - Branch `adobe/subject-motion-edge` (commit 755a68e, 36 tests) merges into 0.4.1: after the user's Object Matte click, one call keeps the crisp outline and adds a soft edge only where the subject moves; `undo` removes it.
   - It closes the gap the branch left open: `subject.render_cutout`, `subject.check` and `subject.use_cutout` all learn the new layer.
   - `subject.check` treats the keyer's soft edge on moving parts as expected, the same way it treats the soft-edge layer, so it does not flag every motion-edge cut-out.
   - It is confirmed only on English After Effects, because the effect settings are found by English names. Say so in the docs, and find the settings by match name where possible.
   - The keyer is passed as a parameter: nothing shipped names a third-party product.

4. **Idle-layer report in `ae_check_comp`.**
   - It flags any layer on screen longer than a threshold with nothing changing on it in that span. It is a report, never a fault.
   - What counts as a change (my call):
     - a keyframe on the layer, its effects or its masks;
     - a keyframe on any parent;
     - a time-driven expression, including Source Text;
     - a text animator in motion;
     - a layer marker;
     - for a precomp, one level down: any keyframe inside it during that span.
   - Exempt, never flagged:
     - footage and audio layers whose source plays;
     - cameras, lights, nulls, adjustment and guide layers;
     - solids and stills that cover the whole frame at the bottom of the stack (grounds and backgrounds).
   - Each flagged layer reports its name, the idle span and how long it lasted. In the finish-line case, a lone UI bar with no keys for 12 s would be flagged.
   - The default threshold is 5 s, configurable per call. Joe's Content repo sets 3 s.
   - In the finish-line reel, a command bar sat idle for 12 s (steer 20).

5. **Read the motion guide first in a host project.**
   - Production-workflow step 1 and the motion-studio skill gain one rule: when the project has its own house style, the first reads are the motion-studio skill and the brief template, then the host's own standard. In the finish-line session, the build read neither until Joe said "lean on comp room".
   - The wording is generic: no project or person is named.

6. **When the reviewer runs.**
   - The motion-review skill, the review reference and the motion-studio skill say the independent reviewer pass comes once, before the user's first look at motion, and after that only on request, not every round.
   - This is everyone's default (see "Who the defaults serve"). Joe stopped the per-round reviews because they added time between builds (steer 25).

7. **Repair the project's check command.**
   - `npm run check` fails on `main` today, for three reasons: a lint error in two scripts, no formatter config (101 files flagged), and a missing `server.json`.
   - The fix makes it pass without reformatting the whole tree in this release: add a formatter config that matches today's code, or scope the check. This is done first, so every other change lands on a green check.

## Constraints

- **Release and push:** nothing is released or pushed without Joe's own yes. The only remote, `public`, is a PUBLIC repository.
- **Tests first:** every code change gets its tests written first. The offline suite, the release tests and the repaired `npm run check` all pass before release.
- **No personal names:** nothing shipped names Joe, his brands or a creator; the arsenal name guard and the release tests enforce this.
- **One After Effects controller at a time.** The channel learner session has After Effects for its proofs; 0.4.1's live checks wait for it or are arranged through the parent session. Inspect the open project before any native write, and never close or replace unrelated work.
- **Git:** commit by path, never `git add -A` (an untracked `.build/` exists).
- **Version:** bump to 0.4.1 through the existing release process, with release notes.

## Approaches considered

- **A, one release with everything:** one build and one review. But it waits on the After Effects work (re-proofs, preset testing), probably a day or more.
- **B, two releases (chosen):** the code fixes reach Joe this week, and each release stays small enough to review properly.
