# Portable motion brief

Scale this to the task. The agent fills routine choices and marks inferred defaults; ask the user only for missing information that changes the result. Keep the brief in the user's project for resumption, not as an editor-level intake questionnaire.

## Project

- Primary message / viewer takeaway:
- Reading order: first → second → last:
- Concept: one sentence describing the evolving picture across beats:
- Duration / aspect / resolution / fps / intended viewing size:
- Capability or document IDs: use only IDs present in the installed library:
- Style: named available style, user-described look, or **none**:
- Brand: supplied constraints or chosen palette/type/material defaults:
- Intensity: restrained / moderate / energetic, with reason:
- Exact target AE project/comp and ownership; preserve unrelated work:
- Inputs: inspected assets, exact approved copy, narration/transcript, reference, factual sources:
- Fonts: requested and resolved installed faces; approved fallback; glyph/fit limits:
- Asset requirements / available native or supplied substitutes / blocked dependencies:
- Delivery: editable project/assets, review clip, master spec:
- Inferred defaults and choices requiring user input, if any:

## Scene N — start/end

- One visual argument; operation (before → action → resolution):
- Star / stable anchor / identity:
- Type roles, exact strings, line breaks and reading holds:
- Start/action/resolution poses and hardest overlap bounds:
- Inspected assets; native/supplied/generated/illustrative/evidence status:
- Material, depth, light, shadow and occlusion:
- Events: frame/time, meaningful change, subject, target, spoken cue, duration/ease:
- Camera subject/destination/purpose, or intentionally static:
- Continuity: shared object, scale reveal, morph, matched framing, gather or deliberate cut; why it fits:
- Incoming/outgoing hand-off: what survives, what it becomes, pivots/coordinate spaces, visibility frames:
- Exact data sources and any explicitly illustrative content:
- Fallback if the chosen asset/font/technique is unavailable:

## Build and observable review targets

- Representative section: hard hand-off plus ordinary explanation/proof:
- Stable owned IDs, resting transforms and preserved expressions/keys:
- Check times: first frame, first-readable, action peak, maximum overlap, hold, seam neighbors, last frame:
- Observable targets: e.g. water meets surface, label stays on paper, rule clears every glyph, one copy visible at hand-off:
- For a source-to-use beat: what visibly leaves the source, what carries it across the seam, and what changes only after recipient contact:
- For type on layered material: measured text-safe area in each settled reading pose; any intentional entrance occlusion ends before the hold:
- Delivery-scale text readability, coverage/alpha, registration and final hold:
- Native captures compared with decoded delivered frames:
- Full-speed rhythm / VO / audio checks and explicitly unavailable checks:
- Expected live project state, editable dependencies and export verification:
- Technical outcome / visual judgment / user acceptance recorded separately:

Measured event density can diagnose a chosen fast construction style; it is not a quota for a slow title or quiet proof. If feedback changes the visual argument, revise the brief before adding local effects.
