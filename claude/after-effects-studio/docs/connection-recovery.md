# Connection and permission recovery

Start with `node scripts/doctor.mjs` in the installed plugin folder. It checks Node, package files and the AE path without launching AE. A passing result does **not** verify macOS Automation or AE scripting permission. In a new Codex task, ask the plugin for `ae_version_info` and `ae_context` before allowing a project write.

| Result | What it establishes | Next action |
|---|---|---|
| Doctor reports missing AE or a bad `AE_MCP_EXE` path | AE was not found at a supported path; no native call was made | Install/open licensed AE 2026 or point `AE_MCP_EXE` to its `.app` bundle, restart the agent host and rerun doctor. |
| `AE_NOT_FOUND` or `NO_INSTANCE` | The requested AE executable or running target was unavailable. The error names whether a request was discarded before pickup. | Check the named app/instance and any open dialog. Open AE and retry a **read-only** context check. Do not open or replace a project as a connectivity test. |
| `AUTOMATION_DENIED` | AppleScript reported macOS denial (`-1743` or explicit Apple-events text); the request was not dispatched into AE. | In System Settings → Privacy & Security → Automation, allow the agent host to control Adobe After Effects. Then retry a read-only context check. Do not treat a generic timeout as proof of this permission state. |
| `DIALOG_OPEN` | A modal dialog blocked scripting. The response may include its text if macOS Accessibility permission allows reading it. | Inspect the actual AE window and decide how to answer the dialog. Preserve unsaved work; do not dismiss a save/replace prompt without understanding it. Then read the project state before continuing. |
| Busy-lock or `TIMEOUT` | A call did not produce a response in time. The message distinguishes a request discarded before pickup from one AE picked up that may still be running. | Do **not** replay a write. Check the AE window for a modal/render/preview, wait for a read-only `ae_context`/item inspection, then compare owned IDs and state with the intended result. Retry only the still-missing operation after that inspection. Do not force-quit AE as routine recovery. |
| Possible scripting-file-access denial | Doctor cannot detect this preference, and a timeout alone does not prove it is off. | In AE Preferences → Scripting & Expressions, verify **Allow Scripts to Write Files and Access Network**. Change it if needed, then retry a read-only connection check. If the failure persists, retain the actual error and project state for diagnosis. |
| Missing linked media | A frame render names the missing footage and does not write a new frame. AE may still show a cached frame or temporarily report no missing items. | Restore the source file, then use `footage.replace` with its path if AE retains the missing flag. Render again and inspect the result. `footage.reload` reports a failure if the source remains missing. |

Permission changes affect the host's security settings; the plugin reports what to check and does not silently grant them. After any failure, preserve the current project, including an untitled or unsaved one. A new task or a higher timeout is useful only after identifying whether the prior call could have changed AE state.
