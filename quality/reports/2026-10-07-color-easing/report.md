# Color keyframe easing repair — 2026-10-07

Status: source fix, offline regression checks and an installed candidate pass; **native AE confirmation is pending**. This is a follow-up to the [AFT-7 warning](../2026-10-07-installed-first-session-1945/report.md), where `keyframe.apply` accepted a four-channel Color key but warned that `setTemporalEaseAtKey` expected one ease element. The scene used linear color keys as a disclosed workaround.

The cause is in `runtime/jsx/helpers.jsx`: `AE.setEase` inferred the number of temporal ease handles from `keyValue().length`. A Color value has four channels, but AE's Color property expects one temporal ease handle. The helper now treats Color like spatial properties for this API. The explicit `keyframe.set_easing` operation previously duplicated the same dimension logic; it now calls the shared helper, so both authoring paths use one rule. Ordinary 2D vectors retain two handles and spatial 2D vectors retain one.

The new `runtime/tests/keyframe-ease.test.ts` executes the actual JSX helper under a minimal host mock and checks the argument lengths for Color, ordinary TwoD and spatial TwoD values. It also verifies the explicit easing operation routes to that helper.
